# API, сессии и AI

## Запуск

```sh
docker compose up --build -d
```

Откройте `http://localhost:5173`, задайте название команды и нажмите «Начать сценарий».
Выберите M7/M8/M10 в Нуре, M12 для города и M5 в Сарыарке. Получится расход 95,
Score 56.54307. Анализ сохранит численный результат; без AI-ключа отобразится
сообщение о недоступности объяснения, а не выдуманный текст.

## API

Записывающие запросы требуют заголовок `X-Requested-With: stikerai`, включая Swagger.
Сначала вызовите `POST /api/session`: он выдаст случайную HttpOnly SameSite cookie.
Браузер отправляет её автоматически; в БД хранится только SHA-256 отпечаток.
Неизвестный или чужой сценарий возвращает 404 на всех маршрутах.

- `GET /api/catalog?dataset_id=UUID` — датасет, каталог, районы, правила и исходный расчёт;
  без параметра выбирается последняя версия.
- `POST /api/scenarios` — `dataset_id`, `team_name`, `request_id` (UUID для повторяемого создания).
- `GET /api/scenarios` — последние 50 сценариев текущей сессии.
- `GET /api/scenarios/{id}` — восстановление сохранённого состояния.
- `PUT /api/scenarios/{id}/decisions` — `expected_revision` и полный список
  `decisions: [{initiative_id, district_id}]`. Для города `district_id: null`.
- `POST /api/scenarios/{id}/preview` — `expected_revision`; требует пять допустимых решений.
- `POST /api/scenarios/{id}/submit` — `expected_revision`; атомарно фиксирует решения,
  сохраняет Calculation и создаёт pending Explanation. Повтор возвращает тот же расчёт.
- `GET /api/scenarios/{id}/result` — сохранённый расчёт.
- `POST /api/scenarios/{id}/copy` — `request_id`; создаёт редактируемый черновик-копию.
- `POST /api/scenarios/{id}/explanation` — запускает/повторяет объяснение.
- `GET /api/scenarios/{id}/explanation` — статус и текст.

Ошибки имеют `detail: {code, message}`. Устаревшая версия возвращает 409
`STALE_REVISION`; frontend перечитывает состояние. Бюджет, конфликт и другие
ошибки бизнес-правил возвращают 422. Невалидный выбор не изменяет сохранённый план.

## AI-конфигурация

В корневом `.env` для Compose задайте `OPENAI_API_KEY` и `OPENAI_MODEL` — доступную
вашему аккаунту модель с поддержкой Responses API и Structured Outputs.
После изменения выполните `docker compose up -d backend`. Для локального Python
экспортируйте переменные в окружении терминала; `.env` автоматически не читается.
Ключ не должен иметь префикс VITE и не передаётся в frontend.

Адаптер использует [официальный формат Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
Он передаёт только синтетические рассчитанные показатели/вклады, использует
`store: false`, структурированную схему, тайм-аут и одну дополнительную попытку
при сетевой ошибке, 429 или 5xx. Ответ валидируется Pydantic. Ошибки провайдера
не выдаются пользователю дословно, чтобы не раскрывать служебные данные.

Calculation хранит неизменяемый JSON-снимок расчёта независимо от AI. Explanation
имеет состояния pending/running/completed/failed, модель, версию промпта и ID
попытки. Запуск дедуплицируется под блокировкой; сетевой вызов происходит после
коммита, без удержания блокировки БД. Завершение старой попытки не перезаписывает
более новую. У зависшей попытки есть lease 90 секунд, после которого разрешён повтор.
Это восстановление по запросу пользователя, а не гарантированная фоновая очередь.

LLM не меняет Score; текстовые рекомендации не являются автоматически
проверенными новыми сценариями. Для проверки рекомендации создайте копию и
рассчитайте новый набор решений.

## Проверки

Из `backend`: `python -m pytest -q`, `python scripts/export_types.py --check`.
Из `frontend`: `npm run build`, `npm run test:e2e`.
CI повторяет API-тесты с PostgreSQL, запускает браузерный путь и Docker smoke test.
Реальные AI-запросы требуют отдельно настроенных реквизитов и не включены в тесты.

## Дополнительные маршруты

- `GET /api/datasets/current` — текущий датасет, районы, мероприятия и базовый Score.
- `POST /api/scenarios/{id}/evaluate` — алиас `/explanation`, с теми же проверками
  сессии и тем же ответом ExplanationRead; численный результат уже должен быть сохранён.
- `GET /api/signals/proposals` и `GET /api/signals/proposals/{id}/aggregates` —
  публичные синтетические сводки. Малые группы возвращают `count: null`.
- `GET /api/mirofish/capability` — состояние настройки без вызова провайдера.
- `POST /api/mirofish/scenario` — опциональный шлюз, требует сессии и заголовка записи.

Для AI доступны `OPENAI_BASE_URL` и `OPENAI_TIMEOUT_SECONDS`. URL должен быть HTTPS
(локально разрешён HTTP); редиректы отключены. В активном адаптере тайм-аут одной
попытки ограничен 40 секундами, значение по умолчанию в Compose — 20.
